# 软件授权链路全面检验

日期：2026-10-27。范围：Meteor Store 的购买、交付、赠码、授权与历史兼容，以及 XNook 1.3.26、XIsland 2.0.13 的 macOS 授权生命周期。

后续状态：用户批准后，本报告中的修复已提交并上线，0052迁移完成，正式包已更新为XNook 1.3.28和XIsland 2.0.15。下文保留发布前的审计记录，最终状态见[上线记录](2026-10-27-license-fixes-release.md)。

## 结论

**基础线上链路通过，但已发布版本不能判定为全面通过。** 反例测试发现退款、并发交付和客户端生命周期等边界问题；主要问题已完成本地修复并复测，尚未提交、部署或重新发布安装包。已上线包和真实用户数据未被替换。

本轮把现象归并为以下八组，不能用此前既有测试通过替代这些新增场景：

| 问题 | 复现与影响 | 本地修复 |
|---|---|---|
| 退款结果不确定或通知乱序 | 支付宝超时后直接视为失败、fund_change=N直接视为退款成功；微信旧失败通知可恢复已确认退款的授权 | 新增单一退款请求记录表；同号查询/重试、终态不可倒退，仅确认全额成功后撤销授权 |
| 付款交付与自动补码并发 | 回调查空后，页面补码先插入父码，回调再插入触发23505并把邮件交付标为失败 | 数据库幂等插入并回读赢家，保留原授权状态 |
| 续费后的到期提醒 | 年付加提前续月的有效期已延长，仍按单笔月付发过早提醒；永久用户也可能收到旧限期提醒 | 按有效订单和历史兑换来源累计最终期限 |
| 解绑与凭据存储故障 | 明确无效设备响应后仍接受缓存；解绑成功但保存失败未及时锁定；临时存储故障恢复后无法重试 | 明确失效即关闭访问，区分读取和写入失败，恢复时不复活已撤销状态、不覆盖坏记录 |
| 停止后的迟到响应 | 客户端已停止监控，迟到激活/刷新仍可保存凭据、重挂定时器或恢复运行 | 请求取消传播、停止标记和请求代次检查 |
| XIsland 到期队列 | 已排队的审批、问题、计划在授权暂停后仍可进入归约；bypass模式下仍会答复 | 在交互归约边界执行授权暂停检查，取消请求并保留历史写入 |
| 购买身份与迟到付款响应 | 游客先进入付款表单，但后端要求已验证账号；换号、同ID邮箱/验证状态变化后旧付款响应仍可能跳转 | 购买前引导登录/验证，锁定账号邮箱，关闭或身份变化后取消并丢弃迟到结果 |
| 诊断与显示 | 页面刷新抹掉旧码迁移/空码错误；成功后残留旧错误；试用显示付费设备解绑；客户端仍使用旧术语 | 保留当前诊断、成功后清除旧错误、试用不显示付费解绑、统一激活码及三个期限 |

退款判断按提供方规则核对：支付宝的请求成功不等于退款成功，N或缺失时需要查询确认；微信ABNORMAL后仍可能转为SUCCESS。[支付宝退款说明](https://aipay.alipay.com/docs/subscribe/api-list/other-basic-interfaces/alipay-trade-refund.html)、[支付宝退款查询](https://aipay.alipay.com/docs/vibe-pay/ai-web-app-payment-qianyi/api-list/alipay-trade-fastpay-refund-query.html)、[微信退款状态指引](https://pay.wechatpay.cn/doc/v3/merchant/4013071031)。

上述退款问题以模拟渠道响应、真实RSA/AES协议夹具和隔离PostgreSQL复现，不是已发生生产退款事故的断言。本轮只读检查发现支付宝配置存在；微信配置缺失、前端保持开发中且未发现微信订单，也未发现站内标记为退款的支付宝订单。没有核对渠道账单。

## 尚未通过或未执行的验收

- **线上修复尚未应用**：网站仍为513a5c8，正式包仍为XNook 1.3.26/XIsland 2.0.13。
- **微信启用阻碍**：当前创建订单直接使用36字符UUID，官方Native接口要求6–32字符；微信保持关闭，本轮未改这条未启用的下单映射，也不声称微信已可真实支付。[官方长度约束](https://pay.wechatpay.cn/doc/v3/merchant/4012791877)
- 未执行真实扣款、真实退款或支付提供方实际回调，不把模拟RSA/HTTP测试称为实款验收。
- 未执行三台物理设备换机、真实休眠/关机跨期、真实Keychain权限弹窗和完整原生窗口流程。模拟时钟、私有通知中心与内存存储通过不等于这些实机验收。
- 安装包仍为既有ad-hoc签名，未Apple公证；本轮没有改变签名资质或系统安全设置。

## 修复上线准备

本地已备好 `0052_payment_refund_attempts.sql`：仅新增一张13列退款请求表、约束和索引；不增加旧订单列，不重写历史订单。上线需先备份并核对迁移账本，先迁移再部署引用新表的代码。存在新退款记录后，不应回退到会误恢复授权的旧退款处理器；回滚保留新表、数据和安全的查询/回调处理，详见 [退款修复说明](2026-10-27-commerce-state-race-fixes.md)。

两款客户端需重新构建并使用新的发布版本号，不能覆盖目前正式安装包的同版本哈希。正式授权公钥与协议保持不变，当前修复没有新建生产密钥。

提交时应只收录本次修改。`src/lib/login-return.ts` 同时包含原日刊工作，本轮只新增 `/pricing` 回跳白名单；任务专用补丁已保存，不能整文件夹带其他改动。
