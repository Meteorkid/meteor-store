# 雅思正文点词查义（2026-11-14）

## 范围与交互

用户要求增加“点击单词自动翻译”，并给出下一步建议。本次在现有雅思对照区实现点词查义，没有自动扩展生词收藏、复习或写作评分。

- 两版正文、逐句与全文模式均可点击英文词。点词开关默认开启，可关闭；整句译文、差异标记和笔记保持独立。
- 桌面浮层靠近所点单词，手机固定底部；非模态，不锁页面滚动。Escape、关闭按钮或外部点击可关闭并恢复词焦点；全站搜索打开时关闭且不抢回焦点。
- 拖选/长按选中文本不触发查询。键盘每句只有一个起始 Tab 入口，左右/Home/End 在该句换词，Enter/Space 查义，避免每个词都变成 Tab 停靠点。
- 返回原形、词性、中文语境义和用法，标注“本文词汇”或“AI 语境释义”。朗读需用户点击，并依赖设备可用英语语音，无音标编造或自动播放。

## 后端与来源

- `POST /api/ielts/word-lookup` 接受严格的 `{slug, segmentIndex, side, word}`，不接收任意用户段落。服务端从当前公开作文读取原句，验证完整词命中后才查询；草稿/下架内容不通过此公开接口查询。
- 只在同一个升级句中完整同词命中 `learning.vocabulary` 时复用已有释义，不能将短语释义当成其中单词的释义，不能跨 low/high 混用。
- 其它词复用现有 DeepSeek 密钥，固定端点与 `deepseek-flash`、关闭 thinking、JSON 输出、500 输出 token、12秒超时及16KB响应封顶。模型只接收点击词与本站公开原句，不接收账号信息。
- 成功结果按规范化词、版本方向与当前原句缓存1小时，最多512项；相同请求合并，最多8个不同在途请求。每次先验证当前公开内容再查缓存，失败不缓存。
- IP 30次/分钟；真正调用模型的未命中请求受全站滚动24小时500次预算限制。Redis失败时拒绝；未配置时使用进程内限流，进程重启会清空内存窗口。所有响应 no-store。
- 外部请求的协议以 [DeepSeek 官方 JSON 文档](https://api-docs.deepseek.com/guides/json_mode/)及[模型说明](https://api-docs.deepseek.com/quick_start/pricing/)为参考。未增加第三方浏览器翻译脚本或下载词库。

## 已修故障

首轮12项点词浏览器回归中4项失败：浏览器自动 scrollIntoView 或 focus 的延迟 scroll 事件在浮层打开后才到达，旧逻辑随即关闭。事件探针复现了 click→fetch→panel-add→scroll→panel-remove（部分 scroll 没实际位移；键盘平滑滚动则仍在进行）。改为外部滚动/resize重新定位，手机保持固定底部，内部滚动不处理；原关闭通路保留。最终32项回归通过。
