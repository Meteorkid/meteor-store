# 每日开源、竞赛与实习

用户选择先加入这三个栏目，继续沿用自动生成与公开，不需要手动发布。

## 来源与边界

- 每日开源项目：从42个策展GitHub仓库中轮换挑选1个，实时核验公开、未归档、未禁用，尊重站内下架记录。它是每日探索项目，不是热榜或“今天新发布”。近期30天按仓库URL排重，期次参与sourceKey，避免项目池永久耗尽。
- 每日竞赛：当前接入Codeforces官方未来赛程，每期最多3场，时间字段是开赛时间，不冒充报名截止。近7天开赛或近期收录且30天内开始的比赛可入选，历史入选项目去重。
- 每日实习：当前接入Databricks与Scale AI官方职位板，主要是海外现场学生／应届岗位，每期最多3条。显示公司、地点、办公方式与资格说明；不根据这些信息判断用户必然符合工作许可要求。

## 真实性保护

两种机会要求来源成功核验在24小时以内、来源无当前失败；岗位还须命中完整职位板v2成员集合，且正文核验时间匹配来源本轮成功时间。

Greenhouse同步先检查完整原始JSON、总数、ID唯一性，再依完整ID集合将已消失的公开／过旧岗位标记为expired。展示仍最多处理20条，但不能用这20条决定其它岗位已关闭；失败不关岗，人工下架／驳回不恢复。没有首次发布日期时不借用更新时间。

当天公开期刊会再过滤已开赛、已关闭或无法核验的机会。真实无有效条目显示empty，来源不可用显示failed，数据库快照不被修改；历史日期保留当日快照。自动化重试仍遵守已发布期刊不重生成的规则。

## 接入与部署

新栏目复用08:40生成、失败补跑和09:30提醒，无新增单独定时器。首次部署后先成功同步一次`codeforces-contests`、`databricks-student-jobs`、`scale-ai-student-jobs`，让职位板生成完整v2成员集合，再运行日刊生成；随后由现有每小时`:27`的同步任务维护。

生产写入前备份数据库与应用产物。回滚应用时保留新增期刊记录和已更新的来源状态，不把旧备份直接覆盖到已有新写入的生产库。
