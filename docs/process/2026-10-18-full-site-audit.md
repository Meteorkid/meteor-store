# 2026-10-18 全站审查、修复与后续计划

## 结论

网站已经具备产品获取、内容阅读、账号、每日自动内容和申请日历这些实际能力。当前最值得投入的方向是安全边界、内容可信度和使用流程的连续性，而不是继续快速增加栏目。首页主体按既有要求保持不变。

本轮以 `25014ad`（线上应用 `9cf8e59`）为审查基线，先在独立工作区修复，再逐文件核对整合回主仓库；未覆盖用户未提交改动。今天的10:00巡检请求合并进本轮，实际刷新时间为北京时间14:07，不能把凌晨结果冒充晨间结果。

## 本批修复

### 安全边界

| 问题 | 修复 | 验证与限制 |
| --- | --- | --- |
| 微信OAuth回调未关联发起浏览器 | 每次随机事务、HttpOnly短期cookie、state内事务摘要；兑换code前校验 | 缺cookie、跨浏览器、无事务旧JWT被拒；保留正常MFA、可信设备和白名单回跳 |
| 后续微信绑定凭证可转发 | bind阶段独立浏览器事务，两种绑定模式均核对；成功清理，验密错误保留短期重试 | 单靠转发URL不能绑定；旧扫码/绑定链接需重新开始；未调用真实微信服务 |
| 备用验密/MFA入口预算不一致 | 主登录与微信绑定共享邮箱预算；MFA登录、微信绑定、管理员关闭MFA共享用户预算 | 换IP/换入口不能重置账号预算；仍保留IP限制 |
| 内存限流满容量会淘汰活动限制 | 先拒绝超额IP；容量满只拒新键，不删活动窗口 | 真实内存limiter复现原10,000键填充绕过；已有窗口计数、到期恢复均测过 |
| 数据库异常时接受已撤销JWT | 身份状态查不到时返回未认证，禁止历史JWT恢复授权 | 正常、撤销、删号、异常分支回归；代价是DB故障期间不能继续使用受保护会话 |
| 验证码同题可反复猜测 | Redis GETDEL/内存同步删除先消费再比较；失败自动换题并清除父表单旧proof | 原16次枚举回归失败；正确挑战/proof仍一次性；单次猜测概率仍存在，不等于强抗机器人 |
| 审核不绑定所读版本 | 页面、API、最终SQL都携带/核对expectedUpdatedAt；撤回严格推进版本 | 真实PG覆盖撤回改稿重提、同毫秒/时钟回拨、旧通过/驳回、正常审核及重复请求 |
| 恢复码并发消费 | 原数组、用户、MFA状态及secret的条件更新，只有实际更新者成功 | 并发夹具与实际Drizzle SQL验证；未做真实双连接恢复码压力测试 |
| 公开搜索缺资源预算 | 两入口共享IP预算、160字符上限；长度差大于2时跳过编辑距离 | 超长/超额在读博客前拒绝；576个正常中英/拼音/模糊查询差分零差异；不声称已证实生产DoS |

### 功能与文案

- RSS的频道、条目、GUID、自引用及页面自动发现链接保留locale；英文阅读器不再被导向默认中文。
- 四个站内应用的登录入口保留原应用，回跳白名单只允许真实appIds；英文名称/副标题正确。
- 免费应用的门控文案改为先获取/免费入库，付费产品仍用购买文案；权限检查保留。
- 双语帮助文档同步五组导航、搜索快捷键、实际Pass覆盖范围，移除“所有未来产品都包含”等过时承诺。
- 管理员关闭MFA允许六位TOTP及合法恢复码，避免原长度校验将动态码一律拒绝。
- 铃铛改从轻量栏目配置导入，不为显示栏目名称直接引入整套Zod schema。未把整站JS体积变化全部归因于这一行。
- 运维手册改为自建PostgreSQL现状；明确五分钟健康调度尚未安装，并修正会造成目录嵌套的回滚示例。
- 注册请求失败后清除已消费的验证码凭证并重新加载挑战，避免用户只能刷新整页才能重试。
- 部署镜像同步使用显式条件捕获失败，避免`set -e`在预定告警分支前直接退出；主站部署和镜像结果分别报告。
