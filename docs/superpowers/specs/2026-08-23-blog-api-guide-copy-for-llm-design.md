# 博客发布 API 指南“复制给 LLM”设计

## 背景

博客发布 API 调用指南页面 `/blog/api-guide` 已展示 `docs/blog-publishing-api.md` 的渲染结果，并提供 Markdown 下载按钮。用户还需要把完整原始指南直接复制给大模型，减少下载文件、打开文件和手动全选的步骤。

## 目标

- 在调用指南页面提供“复制给 LLM”按钮。
- 复制内容必须是 `docs/blog-publishing-api.md` 的完整 Markdown 原文，而不是页面渲染后的纯文本或 HTML。
- 成功和失败均提供明确、可恢复的界面反馈。
- 中文和英文页面显示对应文案。

## 非目标

- 不生成额外提示词或修改指南正文。
- 不复制页面链接、HTML 或选中的局部内容。
- 不修改 `/api/guide` 的响应格式和下载行为。
- 不引入新的剪贴板依赖或通用按钮抽象。

## 方案

### 数据流

页面继续由服务端读取并渲染 Markdown。新增的客户端按钮仅在用户点击时执行以下流程：

1. 请求现有 `GET /api/guide`。
2. 检查响应是否成功，并以文本形式读取完整 Markdown。
3. 调用 `navigator.clipboard.writeText` 写入剪贴板。
4. 显示短暂的成功反馈，然后恢复初始文案。

按需请求避免把整篇 Markdown 作为属性传入客户端组件，也继续以 `docs/blog-publishing-api.md` 为唯一内容来源。

### 组件边界

新增一个职责单一的客户端组件，负责请求、剪贴板写入和按钮状态。调用指南页面只负责传入当前语言，不承担浏览器 API 逻辑。

按钮与现有“下载 Markdown”按钮并列，沿用 `glass` 材质和当前按钮尺寸。中文文案使用“复制给 LLM”“已复制”“复制失败”，英文使用对应的自然表达。

### 状态与错误处理

按钮包含四种状态：空闲、复制中、成功、失败。

- 复制中禁用按钮，防止重复请求。
- HTTP 非成功响应、读取失败或剪贴板权限失败统一进入失败状态。
- 成功或失败反馈短暂显示后恢复空闲状态，用户可以再次操作。
- 使用可被辅助技术感知的状态文案，不只依赖图标或颜色表达结果。

## 测试与验收

组件测试覆盖：

- 点击后请求 `/api/guide`。
- 将响应中的完整 Markdown 原样传给剪贴板 API。
- 成功时显示“已复制”反馈。
- 请求失败或剪贴板写入失败时显示“复制失败”，且可再次点击。

人工验收覆盖中文和英文页面、下载按钮不受影响，以及复制结果与 `docs/blog-publishing-api.md` 原文一致。

## 风险

剪贴板 API 可能因浏览器权限或非安全上下文不可用。页面不尝试自动降级到旧式 `document.execCommand`；失败时明确提示并允许用户继续使用已有下载按钮，保持实现简单且不引入过时 API。
