# 密码重置设计

## 目标

补齐登录页已有但未接通的“忘记密码”入口。重置链接只允许修改密码，不签发登录会话；完成后用户必须回登录页重新输入新密码。

## 安全边界

- 请求接口无论邮箱是否存在、是否已验证、发信是否成功，都返回同一成功响应，避免账户枚举。
- 只向已验证账户发送重置邮件。
- 重置令牌使用独立 JWT 派生密钥、独立 audience，包含 `userId`、规范化邮箱和签发时的 `tokenVersion`，有效期 1 小时。
- 链接把令牌放在 URL fragment，避免进入服务端访问日志和 Referer；客户端读取后立即清理地址栏。
- 成功重置时条件更新当前 `tokenVersion` 并递增，使令牌单次有效，同时让所有旧会话失效。
- 请求和提交接口分别按 IP、邮箱或令牌身份限流，身份类接口在限流后端异常时关闭失败。

## 流程

1. 用户在登录页进入 `/forgot-password`，提交邮箱。
2. `POST /api/auth/forgot-password` 返回统一提示；若命中已验证账户则发送 Resend 邮件。
3. 邮件链接进入 `/reset-password#token=...`。
4. 页面读取并清理 fragment，用户输入两次新密码。
5. `POST /api/auth/reset-password` 校验令牌、账户身份与 `tokenVersion`，更新密码并递增版本。
6. 页面跳转登录入口；接口不创建会话。

## 非目标

- 不通过验证链接自动登录。
- 不为未验证账户自动补发验证邮件。
- 不新增持久化 token 表；`tokenVersion` 已提供单次消费和会话撤销能力。
