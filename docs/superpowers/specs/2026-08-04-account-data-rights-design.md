# 账户订单与数据权利设计

## 目标

补齐账户中心已承诺但缺失的订单列表、个人数据导出和自助注销。销售暂停只禁止新订单，不影响历史订单查看。

## 订单

- `/orders` 仅按当前已验证会话邮箱查询订单，订单详情继续逐笔校验同邮箱身份。
- 销售开关不再遮挡历史订单详情。
- 数据库查询只选择页面需要的用户和订单列，不读取密码哈希或订单访问令牌。

## 数据导出

- `GET /api/auth/export` 输出不缓存的 JSON 附件。
- 包含账户资料、订单、授权码、邀请码兑换、投稿、评论、标签、提议、反馈、收藏、点赞和举报。
- 不包含密码哈希、会话令牌、订单访问令牌或交付认领内部字段。
- 每个账户每小时最多导出 3 次，限流后端异常时拒绝请求。

## 账户注销

- 用户必须提交当前密码和固定确认短语；管理员邮箱禁止自助注销，需先从 `ADMIN_EMAILS` 移除，避免后台锁死。
- 先执行可重复的子数据清理，最后删除用户行。中途失败时用户会话仍有效，可安全重试。
- 删除投稿、评论、收藏、点赞和邀请码兑换；反馈/话题提议移除邮箱；举报保留审核留痕但匿名化处理人。
- 订单和授权记录按隐私政策的法定/合同留存期保留，账户重建后仍可按同一已验证邮箱找回。
- 删除用户行后销毁当前 cookie；旧设备因用户不存在自动失效。
- 已发布投稿被删除时刷新博客、RSS、标签和 sitemap；R2 头像与用户前缀博客图片尽力清理，失败只留下待清理孤儿对象。

## 回滚

订单列表和导出均为只读，可直接回退应用。注销属于用户主动触发的不可逆操作，界面必须明确提示；部署前不对现有生产账户执行任何删除。
