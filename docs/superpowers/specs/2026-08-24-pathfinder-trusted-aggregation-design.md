# Pathfinder 可信信息聚合与大学生学习路径设计

日期：2026-08-24

## 目标

将现有“一次性 7 天 AI 计划 + 用户自带 API Key”的 Pathfinder，重做为面向中文大学生的可信信息中心：聚合开源项目、竞赛、实习与 AI 动态，并将经过审核、具备学习价值的条目转化为 4–8 周可执行学习路径。

核心成功标准：

- 用户无需登录、无需配置模型即可浏览与生成路径。
- 每条公开信息都能追溯原始来源、发布时间或发现时间、最后核验时间。
- AI 动态只用于帮助判断方向，不直接算作学习任务。
- 路径中的资源必须来自已发布、可用于学习的目录条目，不得编造 URL、截止时间或资格。
- 每一步必须包含预计时间、行动、产出证据和替代方案。

## 产品结构

Pathfinder 使用独立子导航和可分享路由：

- `/[locale]/pathfinder`：发现页，包含精选、近期截止、最新机会、AI 动态和聚合统计。
- `/[locale]/pathfinder/opportunities`：开源项目、竞赛、实习目录与复合筛选。
- `/[locale]/pathfinder/directions/[slug]`：AI、前端、后端、数据四条方向说明、技能地图与推荐机会。
- `/[locale]/pathfinder/items/[id]`：条目详情、适用对象、前置技能、预计投入、来源与核验信息。
- `/[locale]/pathfinder/plan`：画像表单、4–8 周路径和本地进度。
- `/[locale]/admin/pathfinder`：来源状态、待审核条目、发布/驳回操作。

桌面端采用主信息流加侧栏，侧栏只承载筛选、近期截止和路径入口；移动端始终单列，筛选进入抽屉。继续使用全站暗色设计、既有字阶与玻璃 chrome，正文卡片不叠加玻璃材质。

## 双层内容架构

公开目录由两层组成：

1. 仓库内静态可信种子：首版 30–50 条官方项目、机会入口和动态来源，保证构建、数据库故障与首次部署时仍有完整体验。
2. Neon 动态目录：定时采集、规范化、去重、审核后发布的条目覆盖或补充静态种子。

数据库读取失败时只记录服务端告警，并在独立 Redis tombstone 可用时安全回退静态种子。若数据库与 tombstone 存储同时故障，生产环境宁可暂时返回空目录，也不能让已下架种子复活。相同规范 URL 的数据库条目优先于静态条目。

## 数据模型

新增三张表，不复用博客 `posts`：

### `pathfinder_sources`

记录来源名称、适配器、站点 URL、来源类型、可信等级、是否启用、是否允许自动发布、同步周期、ETag/Last-Modified、游标、最近成功、最近错误与连续失败次数。

### `pathfinder_items`

记录来源、外部 ID、规范 URL、URL 哈希、内容类型、双语标题与摘要、双语组织方、主方向与受控多方向、难度、预计时长、原币种费用与双语说明、设备、网络、双语地域、远程状态、双语资格、双语截止原文、官方日期与标准时间、发布时间、发现时间、核验时间、状态、是否可进入学习路径、是否必须人工核对复杂资格、审核人、内容哈希。

状态为 `pending | published | rejected | archived | stale | expired`。官方只有日期但没有时区时保存 `deadlineDate`，只有明确时区时才保存 `deadlineAt`；时刻完全未知时只保留双语 `deadlineText`，绝不推测。外币费用保留官方金额和币种，不使用即时汇率伪造人民币金额。

### `pathfinder_item_tags`

以 `(itemId, dimension, tag)` 为复合主键，维度为 `topic | skill | career | format`。标签不存 JSON，以支持数据库筛选与聚合。

关键唯一约束：`(sourceId, externalId)` 与 `urlHash`。常用索引覆盖发布状态、类型、截止时间与学习资格。

## 聚合与审核

流水线：

```text
官方 API/RSS/白名单页面
→ 解析
→ URL、时间与枚举规范化
→ 硬校验
→ URL/外部 ID 去重
→ pending
→ 管理员审核
→ published
→ 定期复核
→ stale / expired
```

首版只实现可维护的适配器：GitHub API 与 RSS/Atom。竞赛和实习以官方入口人工种子为主，后续为单个来源增加专用适配器。禁止公开请求传入任意抓取 URL，避免 SSRF；每个来源设置超时、条数上限和低并发。只保存事实字段、原创短摘要和原文链接，不镜像完整正文或外部图片。

受保护的 `/api/cron/pathfinder-sync` 使用 Bearer secret，由阿里云 crontab 调用。同步按来源隔离失败并幂等 upsert；写接口执行限流。自动采集默认进入待审，只有稳定、可信且明确配置 `autoPublish` 的官方源才可直发。

## 路径引擎

路径生成以确定性逻辑为核心：

1. 校验学生画像：目标、方向、年级、基础、每周时间、设备、预算与限制。
2. 只读取 `published && learningEligible` 且不要求额外人工资格核验的目录条目。
3. 先剔除已过期、设备不符、预算超限、基础无法衔接和明显资格不符的条目。
4. 按目标类型、方向、难度衔接、可信度、时效和投入产出排序。
5. 生成 4–8 周阶段：准备、练习、真实行动、交付与复盘。
6. 每周包含明确任务、预计分钟数、目录条目 ID、完成证据与替代项。
7. 对竞赛和实习倒排截止日期；时间不足时明确提示，不伪造可完成承诺。

默认完全不调用模型。未来如配置服务端模型，只能对已选定候选进行说明润色，模型输出再次校验 ID；失败时确定性结果不受影响。旧 BYOK 设置页、模型配置组件和供应商白名单删除。

路径与勾选进度首版保存在版本化 `localStorage` 中，不建立用户进度表；目录条目失效或版本变化时提示重新规划。

## 安全与异常

- 危机与医疗关键词继续本地拦截，返回求助引导，不进入职业/学习规划。
- 公开读取 API 对查询长度、分页大小和枚举做严格校验。
- 公开读取 API 还执行按 IP 的温和限流；页面缓存与目录 API 在审核或维护状态变化时主动失效。
- 路径 POST 在 JSON 解析前执行 32KB 流式体积上限；限流正确区分 IPv4 与 IPv6 客户端。
- Cron 与管理员写操作限流、鉴权并写管理员审计日志。
- 非管理员访问后台统一 404，metadata 同样不泄露后台存在。
- 外部同步使用固定白名单来源、禁止重定向到非允许域名、限制响应体和超时。
- 数据库不可用时公开页只在独立 tombstone 可用时安全回退；后台与同步接口明确失败，不伪装成功。

## 验收范围

- 发现、机会、方向、详情和路径页面均支持中英文并通过移动端单列验收。
- 搜索与类型/方向/难度/远程/截止筛选可组合，并反映在 URL。
- 可从任一可学习条目进入路径表单，生成 4–8 周计划并本地保存进度。
- 每条卡片和详情展示来源、可信度与核验时间；过期条目不进入新路径。
- 后台可分页搜索全部生命周期状态，也能通过 Redis + 数据库双记录立即下架静态种子，并受审计地恢复到待审核。
- 数据库迁移、静态种子、动态查询、同步、审核与路径核心具有单元测试。
- `pnpm test`、`pnpm lint`、`pnpm build` 通过；浏览器检查 390、768、1280 宽度。

## 上线边界

数据库迁移是 additive：新增表和索引，不修改现有业务表。上线顺序为先备份/创建 Neon 恢复点并执行迁移，再部署应用，最后配置 cron secret 与服务器 crontab。回滚应用时可保留新表；自动同步默认关闭，不会在未配置来源时写生产数据。
