# 雅思写作对照 · 设计（2026-11-14）

## 要解决的问题

雅思写作提分最有效的方式不是背模板，而是**看见同一句话从 5 分写到 8 分差在哪里**。
但市面上多数范文书只给高分作文：读者知道它好，说不出好在哪里，更不知道「我现在的写法该怎么改」。

所以这一页只做一件事：**同一篇作文写两遍**。左边 5 分档，右边 8 分档，论点、顺序、例子完全一样，
只有词汇、句式、衔接和任务回应在变；每一句都能点开看这一句具体改了什么。

## 内容模型：为什么正文存「对齐句子」而不是两篇文章

```
pair = { slug, task, category, topic, status, sortOrder,
         content: { prompt, title, bandLow: 5, bandHigh: 8,
                    segments: [{ paragraph, low, high, focus, note:{zh,en} }],
                    criteria: [{ key: TR|CC|LR|GRA, note:{zh,en} }],
                    takeaways: { zh[], en[] } } }
```

- **两版全文由 segments 推导**（`essayParagraphs`）。正文不存两份，就没有「左边改了右边没改」的中间状态，
  左右两栏永远逐句对齐——这是这个页面唯一不能出的错。
- `paragraph` 从 1 连续编号；协议层（`IeltsPairContentSchema`）强制段落连续、每段两版句数一致。
- `focus` 标出这一句的升级维度（任务回应 / 衔接 / 词汇 / 句式 / 准确性），页面据此做筛选与高亮。
- `note` 中英双语，要求写到「哪个词换成了哪个词、为什么更高分」，不接受「更高级」这类空话。
- 内容也进 CI：`src/lib/ielts/__tests__/curated-content.test.ts` 检查协议、段落对齐、词数区间与说明完整度。

## 内容从哪来：文件 + 数据库

两个来源，运行时按 slug 合并（`src/lib/ielts/catalog.ts`）：

| 来源 | 位置 | 作用 |
|------|------|------|
| 精选（curated） | `src/data/ielts/batch-*.ts` | 随代码上线，任何环境打开都有内容；改动可 diff、可评审 |
| 生成/覆盖（generated） | 表 `ielts_pairs` | 后台生成的新对照、或对精选组的改写/下架，不必等部署 |

合并规则（每一条都有测试）：

1. 以精选内容为底；
2. 数据库行 `hidden` → 该 slug 整体消失（文件版本也不回填，这就是「下架」）；
3. 数据库行 `published` 且有 content → 整组替换；
4. 数据库行 content 为空 → 只覆盖状态与排序；
5. 数据库行 `draft` → 不公开；
6. **读数据库失败 → 退回只用精选内容**，公开页不会因为数据库抖动变空白。

## 自动生成

`src/lib/ielts/generator.ts` 走与每日英语同一条路（DeepSeek、同一把 key、按字节封顶），
但产物要求更严：提示词约束「8 分版是 5 分版的升级、逐句对齐」，zod 校验 + 词数校验兜底，
不合法重试一次，再不行就报错——**绝不把对不齐的左右两栏写进内容库**。

生成结果是**草稿**，后台点「发布」才公开；生成类动作单独限流（防手滑与刷额度）。

## 页面

- `/[locale]/study/ielts`：对照库。按题型（Task 2 / Task 1 学术 / Task 1 书信）与主题筛选，
  卡片显示两版词数与升级处数；登录后显示「已学 / 收藏」徽标。
- `/[locale]/study/ielts/[slug]`：题目 + 左右对照 + 四项评分维度对比 + 可抄走的写法 + 上一组/下一组。
  - 逐句模式（默认）：一行一对句子，点开看说明；可按升级维度筛选（其余句淡出）。
  - 全文模式：两栏各成一篇完整文章，适合先自己读一遍。
  - 移动端不并排（并排会让每句折成好几行），改为同一行上下堆叠，顺序与桌面一致。
- 学习状态：`ielts_progress` 一人一组一行，`studiedAt` / `bookmarkedAt` 各自可空；
  未登录也能读全文，只是不能保存状态（按钮位置给登录链接并回跳本页）。

## 可见性与 SEO

- **公开可读、可收录**：范文是共享内容而非私人数据，游客直接读；这一页是学习区里唯一进 sitemap 的页面
  （`/study/ielts` 与每一组详情页都带双语 alternates）。
- 其余学习页保持 `noindex` 且登录可见，边界不变。

## 边界

- 首批 6 组：Task 2 四组（观点 / 讨论 / 问题解决 / 利弊）、Task 1 学术一组（表格题，题干内嵌完整数据）、
  Task 1 书信一组（正式投诉信）。
- 生成器依赖 `DEEPSEEK_API_KEY`；本地未配置时后台给出可读报错，不影响公开页。
- 不做「自己写一段再评分」：那是另一条产品线（写作批改），需要模型对自由输入打分，误差与成本都不同量级。
