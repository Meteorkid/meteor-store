# Meteor Store 帮助中心扩展与新手教程 · 设计文档

日期：2026-08-10

状态：已确认，待实施

## 1. 背景

第一版帮助中心已经把 `/docs` 从重复的产品目录改造成静态帮助中心，并发布了 6 篇中英文问题文章。现有方向正确，但仍有三个明显缺口：

1. 首页按四个分类排成普通两列网格，文章数量不均时会产生大块空洞；移动端还存在长文本被裁切的风险。
2. 内容主要覆盖“遇到问题后怎么办”，没有告诉第一次访问网站的用户“网站有什么、应该从哪里开始”。
3. 文章数量增加后，只有分类浏览和全站 Spotlight 搜索不足以承担帮助中心内的快速查找、连续学习和跨分类推荐。

本设计在不改变 `/docs` 与现有文章 URL 的前提下，将帮助中心扩展为“双轨结构”：用户既可以按新手路径连续学习，也可以按具体问题搜索或按主题浏览。

本设计是 [2026-08-09-help-center-design.md](./2026-08-09-help-center-design.md) 的第二阶段扩展。第一阶段已经实现的安全边界继续有效；两份文档冲突时，以本文为准。

## 2. 已确认的产品决策

- 一次性覆盖网站面向普通用户的主要功能，共发布 26 篇教程，而不是先上线少量文章。
- 目标用户包括普通访客、注册用户和文章投稿者；不包含管理员后台。
- 26 篇文章全部同时提供中文和英文正文。
- 信息架构采用“新手路径 + 问题知识库”双轨方案。
- 首页 FAQ 保持原有界面和内容，数据抽成共享来源后可在帮助中心再展示一份。
- 帮助中心增加独立搜索框，匹配标题、摘要、关键词和拼音，不新增搜索服务。
- 只为真正复杂的网站功能和产品能力写专门教程，不给每个产品复制一份产品详情页。
- 高摩擦流程提供真实、脱敏的图片指引；其他文章以文字步骤为主，后续可继续补图。
- 用户反馈不会自动公开。官方筛选、核实、脱敏后，更新现有文章或发布新的静态帮助文章。

## 3. 目标与成功标准

### 3.1 目标

1. 第一次访问的用户能在帮助中心快速理解网站提供的主要功能，并选择适合自己的入门路径。
2. 已有明确问题的用户能通过独立搜索、分类或相关文章在较少操作内找到答案。
3. 用户能沿着免费获取、邀请码兑换、购买使用、博客投稿或在线体验路径连续完成任务。
4. 所有帮助文案只描述项目已实现的行为，不创造虚假的交付、更新、授权或服务承诺。
5. 帮助内容继续保持静态、可审查、可版本化，不引入新的数据库、管理后台或发布系统。

### 3.2 可验证成功标准

- 帮助中心共登记 26 个稳定 slug，现有 6 个 slug 全部保留。
- 每个 slug 都有非空的中文和英文 Markdown，共 52 份正文。
- 5 条新手路径中的文章引用全部有效，并能在详情页显示正确的路径进度与前后导航。
- 独立搜索支持中英文、关键词、中文全拼和拼音首字母，并可用 `?q=` 分享搜索状态。
- 详情页自动生成二、三级标题目录和稳定锚点。
- 375、768、1024、1280px 下首页和详情页均无横向溢出。
- 购买相关内容在 `SHOW_PRICING=false` 时不会出现在索引、搜索、路径、静态参数或 sitemap 中，直接访问返回 404。
- 关键流程截图不含个人邮箱、订单号、授权码、令牌或其他敏感数据。
- 现有 Markdown XSS 回归测试、类型检查、Lint、单元测试和生产构建全部通过。

## 5. 目标用户与新手路径

帮助中心首页提供 5 条任务导向路径。路径只引用文章，不复制正文。

### 5.1 免费获取产品

1. 第一次使用 Meteor Store
2. 了解网站中的产品类型
3. 注册并验证邮箱
4. 免费获取产品
5. 在“我的产品”中打开或下载

### 5.2 使用邀请码

1. 第一次使用 Meteor Store
2. 注册并验证邮箱
3. 兑换邀请码
4. 在“我的产品”中打开或下载
5. 必要时查看授权码使用说明

### 5.3 购买并使用产品

仅在 `SHOW_PRICING=true` 时展示。

1. 浏览和比较产品
2. 了解产品类型及在线试用的边界
3. 购买单品或 Meteor Pass
4. 购买后获取产品
5. 在“我的产品”中打开或下载

### 5.4 参与博客社区

1. 浏览博客分区、标签与 RSS
2. 注册并完善个人资料
3. 点赞、评论、收藏与举报
4. 投稿并查看审核状态

### 5.5 在线体验与学习

1. 了解在线试用与正式授权的区别
2. 使用 Playground
3. 使用 Pathfinder
4. 需要时查阅产品获取与使用教程

路径卡片链接到第一篇文章，并带 `?journey={id}`。详情页只接受元数据中存在、且确实包含当前文章的路径 id；合法时显示“第 N / M 步”和上一篇、下一篇，并在链接中继续保留该参数。直接打开文章或参数无效时，不显示路径进度，改用普通相关文章。

SEO canonical 始终忽略 `journey` 查询参数，指向文章的规范 URL。

## 7. 页面与交互设计

### 7.1 帮助中心首页 `/docs`

页面按以下顺序组织：

1. 紧凑的眉标、标题和一句定位说明。
2. 帮助中心专用搜索框。
3. 5 张新手路径卡片。
4. “热门问题”，复用首页 FAQ 的同一份数据。
5. 可换行的分类锚点导航。
6. 完整教程库。
7. “没有找到答案？”反馈区。

完整教程库不再把多个分类放进普通两列分类网格。六个分类按纵向全宽区块排列，每个分类内部在宽屏使用两列文章条目，在窄屏使用一列，因此不同分类的文章数量不会互相制造空洞。

文章条目采用安静的实色或细分隔线材质，不给所有正文索引卡片套 `.glass-card`。玻璃只用于搜索框和新手路径等真正可交互的重点区域，且背景光晕覆盖这些玻璃组件所在的完整区域。

视觉层级：

- 文章标题使用 `t-title-4`。
- 摘要约 15px，颜色不低于 `white/60`，权重高于日期。
- 更新时间继续使用 `t-footnote` 和 tabular numerals。
- 英文页避免连续显示语义重复的 “HELP CENTER / Help Center”；眉标改为 “Official Support”。
- 分类和条目都使用语义化 `section`、`ul`、`li`。

### 7.2 独立搜索

搜索只使用本地元数据，不读取或发送 52 份 Markdown 正文，也不新增 API：

- 匹配本地化标题、摘要、关键词、拼音首字母和全拼。
- 多个词项使用 AND 语义，与现有 Spotlight 的基本匹配习惯一致。
- 默认按匹配分数排序，再用分类顺序和文章顺序稳定排序。
- 输入同步到 `?q=`；使用 replace 语义，避免每输入一个字符都增加浏览器历史。
- 清空输入后移除 `q` 参数并恢复普通首页内容。
- 结果区域使用 `aria-live="polite"` 报告结果数量；空结果直接提供反馈入口。
- 页面服务端预先构建必要的拼音字段，客户端只筛选已序列化字符串，避免把整份全站索引或不必要的服务端数据打进客户端 bundle。
- 商业文章在生成搜索数据之前过滤，客户端不会收到隐藏文章的标题或 URL。

### 7.3 新手路径卡片

- 卡片说明完成该路径后能得到的结果，并显示步骤数。
- 点击进入第一篇文章，带合法的 `journey` 参数。
- 购买路径只在销售功能开放时出现。
- 路径在移动端单列排列，不使用横向滚动容器。
- 卡片 hover 仅在 `hover: hover` 且 `pointer: fine` 时启用；键盘焦点和 active 状态不依赖 hover。

### 7.4 首页 FAQ 复用

把 FAQ 的问题 key、答案 key、商业标记和可选的对应帮助文章 slug 移入浏览器安全的数据文件。首页 `FAQSection` 继续使用原有组件、翻译 key、顺序和可见内容，因此首页视觉与文案不变。

帮助中心的“热门问题”复用同一份数据：

- 有对应正式文章时，显示“查看完整教程”链接。
- 没有对应文章时，仍可展开阅读 FAQ 答案。
- `SHOW_PRICING=false` 时沿用现有商业 FAQ 过滤规则。

### 7.5 文章详情 `/docs/[slug]`

宽屏采用“正文 + 右侧目录”布局：

- 正文阅读宽度约 `68ch`。
- 右侧目录只列二、三级标题，使用 sticky 定位，并高亮当前锚点时保持低干扰。
- 移动端把目录放在摘要下方，使用原生 `<details>` 折叠，不为展开行为增加客户端状态。
- 面包屑和底部返回链接保持小字号外观，但真实触控高度不低于 44px。
- 相关文章使用 `ul/li`，明确关联文章优先，同分类文章作为回退。
- 处于新手路径时显示路径进度、上一篇和下一篇；不在路径中时只显示相关文章。
- 外链在视觉上显示外链标识，并向读屏用户说明会在新标签页打开。
- 正文继续使用普通暗色背景，不给长文套玻璃容器。

反馈 CTA 使用 `/feedback?type=question&source=help&article={slug}`。反馈页只接受白名单中的 article slug；合法时预填本地化的文章标题和相对地址，非法值、重复数组参数或任意文本均忽略。首页反馈入口仍只传 `type=question`。

### 7.6 响应式与动态效果

- 主要 flex/grid 子项使用 `min-w-0`，可变内容容器使用 `w-full`。
- 长标题、URL、代码和连续英文允许安全换行；代码块自身可横向滚动，但不能推动页面宽度。
- 分类锚点按钮可换行，每个交互目标至少 44px 高。
- 375、768、1024、1280px 都必须满足 `document.documentElement.scrollWidth === document.documentElement.clientWidth`。
- hover 位移只在精细指针设备生效。
- `prefers-reduced-motion` 下关闭帮助页 transition、transform 和全局锚点平滑滚动，避免把动画变成瞬移。

## 8. 数据模型与数据流

### 8.1 文章与分类元数据

`src/data/help-articles.ts` 继续作为标题、摘要、分类、顺序、搜索关键词和关系的唯一数据源，并扩展为：

```ts
export type HelpCategory =
  | 'getting-started'
  | 'account'
  | 'products'
  | 'community'
  | 'tools'
  | 'support';

export type HelpArticleKind =
  | 'tutorial'
  | 'how-to'
  | 'troubleshooting'
  | 'policy';

export interface HelpArticleMeta {
  slug: string;
  category: HelpCategory;
  kind: HelpArticleKind;
  order: number;
  readingMinutes: number;
  updatedAt: string;
  featured?: boolean;
  commercial?: boolean;
  relatedSlugs?: string[];
  title: { zh: string; en: string };
  excerpt: { zh: string; en: string };
  keywords: { zh: string[]; en: string[] };
}
```

`readingMinutes` 是用于列表快速判断篇幅的近似正整数，不作为正文精确计时器。文章结构、标题和摘要仍不写进 Markdown，避免与客户端可用元数据重复维护。

### 8.2 新手路径

路径与文章分开定义：

```ts
export interface HelpJourneyMeta {
  id: 'free' | 'invite' | 'purchase' | 'community' | 'online-tools';
  order: number;
  commercial?: boolean;
  title: { zh: string; en: string };
  excerpt: { zh: string; en: string };
  slugs: string[];
}
```

路径只保存有序 slug。测试保证每个引用存在、单条路径内部不重复、商业路径与商业文章的可见性一致。文章可以被多条路径复用，不在文章元数据中重复保存路径成员关系。

### 8.3 可见性

提供一个可测试的可见性函数，首页、搜索、路径、详情、静态参数、相关文章、Spotlight 和 sitemap 全部复用：

```ts
isHelpArticleVisible(article, showPricing)
```

当销售关闭时：

- `commercial: true` 的文章不会进入任何列表、搜索索引、路径或 sitemap。
- `generateStaticParams` 不生成对应组合。
- 直接请求隐藏文章由页面再次校验并返回 404，不能只依赖静态参数。
- 显式相关文章和路径在输出前过滤，不能留下指向 404 的链接。

### 8.4 正文文件

正文继续按语言与 slug 存放：

```text
content/help/
  zh/{slug}.md
  en/{slug}.md
```

`src/data/help.ts` 仍是仅服务端加载层：

- slug 必须先命中元数据白名单，外部输入不能参与任意文件路径拼接。
- `getHelpArticle` 只读取当前语言的对应文件，缺失或空正文是发布错误。
- `getRelatedHelpArticles` 先按 `relatedSlugs` 顺序返回明确关系，再用同分类补足最多 3 篇；全程过滤隐藏文章和当前文章。
- 新增按 id 查找路径、验证当前文章在路径中的位置以及计算前后项的纯函数。

### 8.5 Markdown 渲染

不另写 Markdown 解析器。现有 `unified + remark-gfm + rehype-sanitize` 仍是唯一基础管线，并抽出可配置的 processor 工厂：

- 普通博客和投稿继续使用现有 `markdownToHtml`，行为不变。
- 帮助文章使用仅服务端的 `renderHelpMarkdown`，返回 `{ html, headings }`。
- 帮助专用 Rehype 插件访问已经解析的 HAST，为 `h2/h3` 生成基于标题文本的 Unicode 安全 id，处理重名后缀，并把目录写入当前 VFile 数据；不手写 Markdown 正则解析。
- sanitize schema 只额外放行帮助渲染实际需要的 heading `id`、图片尺寸、`figure/figcaption` 等属性和元素。
- 原生 HTML 仍被丢弃，外链继续限制为安全协议并携带 `noopener noreferrer`。

帮助文章中的本地图片由帮助专用异步插件处理：

1. 只接受 `/help/{当前 slug}/...` 白名单路径并拒绝路径穿越。
2. 用已有 Sharp 读取图片元数据，补充 `width`、`height`、`loading="lazy"` 和 `decoding="async"`。
3. Markdown 图片 title 作为可选图注，生成 `figure/figcaption`。
4. 缺失文件、无法读取尺寸或空替代文本由测试阻止发布，而不是在生产静默降级。

这条帮助专用路径可以异步处理；现有同步 `markdownToHtml` API 保持不变，避免扩大改动范围。

## 9. 图片指引规范

- 不含界面文字、两种语言完全相同的图片放 `shared`。
- 含界面文字的图片分别放 `zh`、`en`。

## 10. 内容模板与写作规范

每篇文章只解决一个明确用户目标，正文不写 `h1`，统一从以下结构中选用必要章节：

1. 你将完成什么
2. 适用场景或开始前准备
3. 编号操作步骤
4. 如何确认已经成功
5. 常见问题与分支
6. 安全或隐私提醒
7. 下一步推荐阅读

不要求每篇机械地出现七个标题；短文章可以合并，但必须包含结果判断和真实边界。

### 10.1 双语规则

- 中文和英文在事实、步骤、链接、安全提醒上完全等价。
- 英文按自然表达改写，不逐字翻译中文语序。
- 产品名、按钮名、路由和状态名以当前界面为准。
- 修改一门语言的事实性内容时，同一次变更必须检查另一门语言。
- `updatedAt` 表示两种语言都完成复核的日期，不能只更新其中一份正文后改日期。

### 10.2 必须遵守的产品事实

- 购买入口受 `SHOW_PRICING` 控制；关闭时购买页和商业教程不可见。
- 付费购买允许游客下单，注册账户是推荐路径，不是强制前置条件。
- 免费入库和邀请码兑换必须登录。
- 免费入库写入 ¥0 已支付订单，但不发授权码、不发确认邮件。
- 只有注册表中的一部分产品能在浏览器内直接打开；其余可能是安装包、命令行工具或外部项目。
- `/apps/{id}/trial` 是免授权试用，不能描述成已获得正式产品。
- 产品下载区、版本号、SHA-256、快速上手和在线试用都是可选能力，不能写成所有产品都有。
- Meteor Pass 不是独立产品，不存在 `/apps/meteor-pass`；月付和年付会到期，买断永久，不自动续费。
- 单品授权优先于 Pass；Pass 只补充用户尚未单独拥有的产品。
- 邀请码用于兑换权益，授权码用于具体产品要求的激活场景，两者不能混称。
- 登录购买通常通过账户关联授权；游客订单和历史授权可能依赖购买邮箱，不能绝对声称换邮箱后一定无法识别。
- 产品没有统一自动更新器、统一更新通知或统一版本说明。
- 博客投稿状态为草稿、待审核、已发布或已驳回；普通用户教程不涉及管理员审核操作。
- 点赞、收藏、评论和举报需要按当前页面的登录要求说明；举报不会自动删除内容。
- macOS 首选右键“打开”或“隐私与安全性 → 仍要打开”，禁止指导关闭 Gatekeeper、开启“任何来源”或运行绕过命令。
- “App 已损坏”或“将损害电脑”属于停止继续绕过并联系支持的场景。

## 11. SEO、可访问性与性能

### 11.1 SEO

- `/docs` 和每篇文章提供本地化 title、description、canonical 与中英文 alternates。
- sitemap 从同一可见文章清单生成 URL，`lastModified` 使用 `updatedAt`。
- 详情页输出 `BreadcrumbList` 与适合教程/帮助文章的 `TechArticle` JSON-LD；结构化数据只描述页面真实存在的内容。
- `journey` 和 `q` 查询参数不形成新的 canonical 页面。
- 未知、隐藏或正文缺失的文章返回真实 404，不回退到相似 slug 或另一语言。

### 11.2 可访问性

- 每页只有一个 `h1`，正文标题从 `h2` 开始，目录层级不跳跃。
- 搜索有可见 label 或等价的无障碍名称、清除按钮和结果数量 live region。
- 所有链接、按钮和折叠控件可用键盘操作并有清晰 `focus-visible` 状态。
- 触控目标不低于 44px；承载信息的文字对比度不低于项目规定的 `white/60`。
- 外链新标签行为有可见标识和读屏提示。
- 图片有描述操作目标的非空 alt；装饰图片使用空 alt 并不进入图注流程。
- `prefers-reduced-motion` 下没有平滑滚动、位移或折叠动画。

### 11.3 性能

- 首页不读取 Markdown 正文，客户端只接收当前语言、当前可见文章的搜索摘要数据。
- 拼音字段在服务端预计算，避免帮助页首屏重复加载不必要的全站搜索索引。
- 截图使用 WebP、稳定尺寸和原生懒加载，控制 CLS 与下载体积。
- 目录在服务端生成；移动端使用原生 `<details>`，不增加不必要的客户端组件。

## 12. 异常与边界处理

- slug 重复、格式非法、分类不存在、分类内 order 重复、日期非法、阅读时长非正整数时测试失败。
- 26 个期望 slug 必须全部存在；首版 6 个 slug 作为永久兼容基线单独断言，新增文章清单从元数据动态推导，避免再次把“当前全部文章”等同于“首版基线”。
- 任一语言 Markdown 缺失、为空、含 `h1`、没有 `h2` 或两种语言目录结构明显不一致时测试失败。
- `relatedSlugs` 引用不存在、引用自身、重复或引用隐藏关系不合理时测试失败。
- 路径引用不存在、路径内部重复或商业可见性不一致时测试失败。
- 本地图片不在当前文章目录、文件不存在、alt 为空、尺寸不可读或格式不符合要求时测试失败。
- 反馈预填只从已知 slug 生成，绝不把任意查询字符串直接写入 textarea。
- 搜索无结果时保持页面可用，提供清空搜索和提交问题两个出口。
- 内容与实际代码或正式政策冲突时，以代码和政策页为准，并在同一次发布前修正文档。
