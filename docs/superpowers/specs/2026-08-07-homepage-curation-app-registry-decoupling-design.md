# Meteor Store 首页精选化与应用注册表解耦 · 设计文档

日期：2026-08-07
状态：已实现

## 1. 背景

首页 `ProductShowcase` 当前默认渲染全部产品，即使区块底部已有“查看全部产品”入口，仍让首页过长。首页还为计算 Pass 文案中的站内应用数量直接导入 `appComponents`，连带加载所有站内应用组件及 CSS，形成主站与应用样式的隐性耦合。

本次只处理两件事：

1. 首页默认展示固定的 6 款精选产品，降低首屏之后的浏览负担。
2. 将站内应用 ID/数量拆成无组件依赖的轻量清单，首页不再导入应用组件注册表。

不调整产品全集页、产品数据结构、Pass 权益、应用门控和试用路由。

## 2. 首页精选行为

### 2.1 固定名单与顺序

默认“全部”状态按以下顺序展示 6 款产品：

1. `xisland` — XIsland
2. `xnook` — XNook
3. `chakra-visualizer` — Chakra Visualizer
4. `skeleton-anatomy` — Skeleton Anatomy
5. `tollow` — Tollow
6. `ex-memory` — Ex-Memory

精选 ID 放在独立的首页数据模块中，不写进组件 JSX，方便后续只调整运营顺序而不改渲染逻辑。

### 2.2 分类筛选

- 初始状态和点击“全部”时，仅展示上述 6 款精选产品。
- 点击“开发者工具”“AI”“设计工具”或“实用工具”时，从完整 `products` 数据中展示该分类下的全部产品，不局限于精选名单。
- 切回“全部”后恢复精选名单及其固定顺序。
- 保留区块底部“查看全部产品”入口，完整目录仍由 `/products` 承担。

现有卡片、网格断点和筛选按钮视觉保持不变，不新增动画。

## 3. 应用清单与注册表解耦

### 3.1 轻量清单

新增无 React、无应用组件、无 CSS 依赖的应用清单模块，导出：

- `appIds`：已接入站内应用的只读 ID 列表。
- `AppId`：从 `appIds` 推导的联合类型。
- `webAppCount`：由 `appIds.length` 推导的数量。

首页只导入 `webAppCount`。因此渲染定价区文案时不会经过 `components/apps/registry.tsx`，也不会把应用 CSS 带进首页依赖图。

### 3.2 类型约束注册表

`appComponents` 继续保留在现有注册表中，供 `/apps/[id]` 与 `/apps/[id]/trial` 渲染实际组件。注册表对象必须通过 `Record<AppId, () => ReactNode>` 的类型校验：

- 清单新增 ID 但未注册组件时，类型检查失败。
- 注册表出现清单之外的 ID 时，类型检查失败。
- 路由仍可用运行时字符串索引注册表，现有 404 与门控行为不变。

这让轻量清单成为可安全导入的元数据源，同时用编译期约束避免清单和实际组件漂移。

## 4. 数据流

### 首页产品区

1. `ProductShowcase` 本地化完整产品数组。
2. “全部”状态按精选 ID 顺序查找产品并渲染。
3. 具体分类状态直接过滤完整产品数组。
4. 产品卡片仍接收原有 `LocalizedProduct`，不改变组件接口。

### Pass 数量文案

1. 首页服务端组件导入 `products.length` 得到产品总数。
2. 首页服务端组件从轻量清单导入 `webAppCount`。
3. 两个数字作为普通属性传给客户端 `PricingSection`。
4. 首页依赖图不再包含应用组件注册表。

## 5. 异常与边界

- 精选 ID 重复或引用不存在的产品属于开发期配置错误，测试必须失败，不做静默兜底。
- 某分类没有产品时沿用当前空网格行为；本次不增加空状态，因为现有四个分类均有产品。
- 应用清单与注册表不一致时由 TypeScript 构建失败阻止上线。
- 不用动态导入改写应用渲染模型，避免影响服务端门控与免门控试用路由。
