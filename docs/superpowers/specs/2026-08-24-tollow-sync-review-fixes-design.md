# Tollow 账号同步审查修复设计

> 日期：2026-08-24
> 状态：已按用户“按推荐方案并连续实施”确认

## 背景

提交 `c035e5f` 已提供 Tollow 登录门控、阅读进度、练习记录和文本收藏，但审查发现六个问题：浏览器缓存没有按账号隔离、远端练习记录没有恢复、收藏缺少离线队列、进度确认存在竞态、原文变化后可能跳错位置，以及筛选项只来自当前分页。

## 目标

- 同一浏览器切换 Meteor Store 账号时，任何 Tollow 数据都不会跨账号读取或上传。
- 阅读进度、练习记录和文本收藏可在不同设备恢复。
- 收藏新增、编辑和删除在断网时仍保留用户操作，并在恢复网络后幂等同步。
- 同步确认不会删除请求发送后产生的更新版本。
- 原文变化后只在能够唯一确认来源时跳转。
- 收藏筛选器展示当前账号全部书籍与标签。

## 账号命名空间

服务端已知的 session `userId` 通过应用注册表渲染上下文传给 `TollowApp`。应用本体在账号存储初始化完成前不渲染，避免子组件提前读取旧键。

所有账号数据使用 `tollow:{userId}:<name>:v2`：

- 阅读进度缓存
- 学习进度与练习会话缓存
- 收藏缓存
- 首次导入标记
- 统一 outbox

旧版全局键只迁移一次：第一个进入新版 Tollow 的登录账号获得旧数据；全局迁移标记写入后，其他账号不再读取旧键。旧键迁移成功后保留一版兼容期，不在本次删除。

## 统一 outbox

outbox 项包含不可变 `operationId`、实体键、类型、版本和 payload。发送时保留快照；响应成功后只在当前队列项的 `operationId` 与版本仍等于已发送快照时删除。若发送期间产生更新，新版本继续留在队列。

进度按 `bookId` 合并，只保留最新 `updatedAt`；练习会话按 `clientRecordId` 幂等；收藏支持 create/update/delete 三种操作并做相邻操作压缩：

- 未确认 create 后继续编辑：合并进 create payload。
- 未确认 create 后删除：移除本地项和 create 操作。
- 已同步收藏的连续 update：保留最新字段。
- delete 覆盖尚未发送的 update。

同步失败后使用有上限的指数退避。新操作、浏览器上线、窗口重新聚焦会立即触发一次同步。

## 练习记录恢复

初始化时分页读取 `/api/tollow/sessions`，按 `clientRecordId` 与账号本地缓存合并。本地同 ID 记录优先，以保留本地可能存在的 mistakes 等扩展字段；远端缺失记录进入 outbox，远端新增记录写入账号缓存。

## 收藏幂等与离线体验

收藏表新增 `client_record_id`，并增加 `(user_id, client_record_id)` 唯一索引。客户端创建时生成 UUID；POST 重试返回已存在记录，不产生重复收藏。迁移只包含 `ADD COLUMN`、回填和 `CREATE UNIQUE INDEX`，不删除现有数据。

收藏抽屉以账号本地缓存为即时数据源：新增、编辑、删除先更新 UI，再写 outbox。服务器列表用于跨设备合并；同步错误保留可见状态并显示“等待同步”。

## 原文定位

跳转时加载当前练习段并按 grapheme 比较：

1. 原偏移切片与收藏 quote 完全一致，沿用原位置。
2. 不一致时在同一段搜索 quote；只有唯一匹配才使用新偏移。
3. 无匹配或多处匹配时标记来源失效、保留快照并禁用后续跳转。

## 完整筛选 facets

收藏列表响应增加独立于分页结果的 `facets`：当前用户全部非空书籍及全部标签。服务层按用户聚合，客户端每次成功加载后更新完整筛选选项，不再从当前 20 条推导。

## 错误处理与兼容

- API 的 `userId` 继续只来自 session。
- 401 停止当前同步实例，不把队列交给后来登录的账号。
- 400 的永久非法操作移入本地失败状态，避免阻塞后续队列；429/5xx/网络错误保留并重试。
- 老收藏没有 `client_record_id` 时用现有主键回填，保证迁移后唯一且无数据丢失。
- 账号导出增加 `clientRecordId`；账号删除沿用现有按 `userId` 删除逻辑。

## 测试

- 两个账号共用 Storage 时 marker、缓存和 outbox 相互不可见。
- 旧版数据只迁移给首个账号。
- 请求飞行期间同书进度更新不会被旧确认删除。
- 练习会话分页恢复、双向合并和幂等。
- 收藏离线 create/update/delete、重试响应丢失、操作压缩。
- 原偏移命中、唯一重定位、无匹配、多匹配。
- 超过一页收藏时 facets 仍覆盖全部书籍和标签。
- 运行 Tollow 聚焦测试、全量 Vitest、TypeScript、ESLint 和生产构建。

## 部署与回滚

先执行 additive migration，再部署应用。应用代码对已有收藏回填后的 `client_record_id` 兼容。回滚应用时保留新增列和索引；它们不影响旧版本读写。
