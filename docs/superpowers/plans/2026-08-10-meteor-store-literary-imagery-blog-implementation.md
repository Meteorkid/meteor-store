## 实施原则

- 只新增中英文博客文章与本计划，不修改星宿、七曜、动画或设计系统代码。
- 中文是第一人称店主原文；英文按相同事实与章节功能自然转写，不逐句硬译。
- 已上线、待修正与未来设想必须明确分开，不把设计示意写成天文计算。
- 文化事实只取支撑文章所需的最小范围，使用权威来源行内链接，不写成考据文章。
- 两篇先以草稿完成审核；2026-08-10 经用户确认后改为 `draft: false`，并获授权只提交本任务四个仓库文件后部署。

## Task 3：事实与文风复核

步骤：

1. 对照网站源码，确认文章只描述已经真实挂载的视觉与交互。
2. 确认没有把 `MeteorShower`、ASCII 莫比乌斯或未来相关阅读星官写成现状。
3. 确认斗宿与北斗、南斗与北斗、七曜次序、等距刻度和固定节气日期的表述准确。
4. 检查文化原义与本站取意分开，不把创意映射说成传统定论。
5. 删除组件清单式段落、空泛宏大叙述和占卜式表达，保持文雅、克制、可读。
6. 核对中英文标题层级、事实状态、链接和核心结论一致。

## Task 4：内容与生产验证

1. 检查两篇 frontmatter 能被现有 zod schema 解析。

3. 运行 `pnpm exec eslint src/data/blog.ts src/lib/markdown.ts`，确认内容没有触发相关代码规则回归。
4. 运行 `pnpm build`，确认两篇正式文章进入生产内容集合且站点仍能完整生成。
5. 统计中文汉字与英文词数，检查尾随空格、空正文、重复 slug 和异常链接。
6. 用 `git status` 与逐文件 diff 确认没有覆盖或暂存用户现有修改。
