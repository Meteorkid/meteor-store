# Meteor Store 商业安全与支付闭环实施计划

> 对应设计：`docs/superpowers/specs/2026-08-04-commercial-safety-payment-design.md`

## 可验证目标

- 生产购买入口关闭，`POST /api/payment` 返回 503。
- 新生成的支付宝地址全部使用 `https://www.imagentx.top`，异步通知无需重定向。
- 支付同步回跳不携带持久订单 token，成功页仍能安全读取当前订单。
- 并发交付只发送一次邮件，失败订单可以重试。
- 零价产品不会创建订单或授权码。

## 顺序

1. 更新生产销售开关为 false，重新部署并验证页面/API。
2. 为支付配置和回跳行为补一条失败测试，完成 canonical URL 修复。
3. 为短时订单查看凭证补失败测试，实现签发/校验和同步回跳。
4. 为交付认领补失败测试，实现统一 `fulfillOrder` 并替换三处重复逻辑。
5. 删除免费订单死分支，用明确响应覆盖零价方案。
6. 运行类型检查、ESLint、全量测试和生产构建。
7. 保持销售关闭部署，验证公开页面、支付 503 和回调路由。

## 迁移

如交付认领需要记录认领时间，新增 nullable `orders.delivery_claimed_at`。迁移只增加列、不回填，旧版本可忽略该列；回滚代码无需立即删除列。
