## 正文（Markdown 直接粘贴）

写了个 macOS 上的悬浮面板，把这些 AI 编程客户端收进一个岛里：Claude Code、Codex、Cursor、Gemini CLI、Qwen、Kimi、OpenCode、Cline、Roo、Aider……

做到第三个月才想明白一件事：**这东西的难点根本不在 UI，在于各家接口的能力完全不对等。**

同样是「代理要写文件了」，有的客户端能让你在外部回一个「允许 / 拒绝」，有的只能让你看一眼它想干嘛，你照样得切回去点。这两类混在一起做，产品就会变成「看起来什么都能干，一用全是割裂」。

所以我最后把接入拆成了三层，只有第一层是普遍能做到的。

**三层能力，别混着说**

**能观察** —— 收到事件，知道哪个会话在跑、在等、报错了。几乎每家都能做。

**能应答** —— 代理提问（单选 / 多选 / 自由文本），能把答案回传。只有部分能做。

**能审批** —— 权限请求在外部决定，并把决定作为**原生批准结果**交回客户端。能做的很少。

分水岭在第三条。**「我收到了一个通知」和「我能替用户批准」是两件事，差一个语义层级。**

具体踩到的几种情况：

- **通知不能当批准依据**。Gemini CLI 有通知通道，但通知本身不是批准接口。你把岛上的按钮接到通知上，客户端那边依然在等它自己的确认，用户看到的是「我点了允许但没生效」。
- **有的客户端压根没有 PermissionRequest 事件**。Factory Droid 就是：只核到观察类事件。这时候正确的做法是不显示任何审批按钮。提前放个假的「允许」，等于让用户对着一个不会生效的开关点。
- **「阻断」不等于「批准」**。Windsurf / Cascade 的前置 hook 能拦住一次调用，但拦住的语义是「我阻止了」，不是「我允许了」。用阻断冒充批准，结果是工具跑不起来，用户以为软件坏了。
- **没有安全应答通道就不做应答**。Roo Code 固定 3.54.0 的任务事件 API，能读任务状态，但没有可靠的回写审批路径。那就只显示状态，审批留在编辑器里。

这几条加起来是我整个项目里最重要的一条原则：**接口不支持，就不要在 UI 上假装支持。** 用户能容忍「这个功能我这里没有」，不能容忍「点了没反应」。

**「配置文件存在」不能证明「接通了」**

第二件反直觉的事：生成一份 hooks 配置，跟它真的被加载、真的被信任，是三件事。

各家客户端普遍还有一层信任确认：你写了配置，它还要你手动进去点一次「允许这些 hooks」。这层不做，文件写得再对也没事件进来。

所以我把接入状态做成六档，不再是「已连接 / 未连接」：

```
待配置     → 配置不完整
待授权     → 客户端明确报告尚未信任
待完成设置 → 需要导入插件 / 选启动入口 / 连外部服务
等待活动   → 配置已就绪，但还没收到真实事件
已接入     → 收到过有效活动
检查失败   → 读不到授权状态
```

关键是**没有「等待活动」到「已接入」的自动推定**。配置文件存在、进程起来了、开关打开了，全都只到「等待活动」。必须收到一条真实任务产生的事件，才允许显示「已接入」。

反过来也一样：客户端有只读的授权查询接口就去查真实状态，别猜。Codex 可以读它的 hooks 列表，拿到启用状态、信任状态和当前定义指纹——查得到就查，查不到就写「检查失败」，不写成「未授权」，也不写成「已授权」。

还有一个细节：**不写别人的信任记录，也不批量信任其他 hooks。** 用户可能有自己的 hooks 在跑，你替他勾上「全部信任」是在改他的安全边界。

**同一个品牌，不等于同一套协议**

这条吃过亏。

- Trae 的 CN 版和国际版是两套协议，CN 的验收结果不能挪给国际版
- Cline 的 VS Code 扩展和它的 SDK CLI 是两条路径，扩展通了不代表 CLI 通
- Zed 和 JetBrains 的内置 AI 拿不到外部通道，能接的只是显式启动的**外部 ACP Agent**，权限还留在编辑器里
- Continue 只能靠 `serve /state` 轮询快照，轮询会漏掉短暂状态——能用，但要老实说它不精确

所以接入矩阵是按「客户端 × 形态」逐格填的，CLI、IDE 插件、桌面端分开记，一个格子验过不能代表隔壁。

**会话身份是另一个坑**

把事件收上来只是开始，还得知道**这条事件属于哪个会话**。

各家给的身份线索都不一样：Windsurf 用 `trajectory_id`，Kimi 有任务树，Qoder 区分原生会话和子任务，GitHub Copilot CLI 有并发 ID 要消歧，Roo Code 会有多个窗口来源。

有一类干脆没有稳定 ID：Amazon Q 的旧 CLI 包装器拿不到稳定的调用标识和回复正文，那就只能做进程级观察，不碰内容。

认错会话的后果很难看——代理 A 的问题显示在代理 B 的卡片上，你点了个允许，批的是另一件事。

**现在到哪一步了**

31 个接入目标，全部都有通过项目契约测试的基础通道；**完整的端到端验收，一个都还没做完。**

差别只在深度：

- Claude Code 走得最远：2.1.234 的隔离真实读取、以及「在岛上拒绝写入」已经实机验过，完整审批、并发权限、子代理和 TUI 还在验
- Codex、Cursor、Gemini CLI、Copilot CLI、CodeBuddy 这些到了「契约测试通过 + 事件类型核对」，真实客户端加载待验
- Aider、Cody、Amazon Q、Zed、JetBrains 只能包一层显式启动器做观察，交互不覆盖

矩阵和每个版本的实际验证记录都公开在仓库里（`docs/compatibility/agent-matrix.json` 和 release-verification 系列），每一格写的是「验到哪一步」，不是「支持 / 不支持」。

我宁可这份表看起来难看，也不想让人装完发现某一行是假的。

**最后**

产品在这：https://imagentx.top/products/xisland ，现在限时免费，领个永久激活码就行。客户端本体闭源，接入矩阵和验收记录是公开的。

2. 有没有人清楚某家客户端其实有对外审批接口、但这里标成了「只能观察」——那说明我漏了，比我自己测出来更值钱
