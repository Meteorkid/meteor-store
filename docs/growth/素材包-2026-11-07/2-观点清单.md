# 观点清单

> 一句话一个。**不要把它们连成段落**，也不要给每条配一句解释。
> 挑 3–5 条用就行，全用会变成论文。

## 关于权限

- 「我收到了一个通知」和「我能替你批准」，差一个语义层级
- Gemini CLI 有通知通道，但通知不是批准接口。按钮接到通知上，用户点了没反应
- Windsurf 的前置 hook 能拦住一次调用，但「我阻止了」不等于「我允许了」
- Factory Droid 我核到只有观察类事件，所以一个审批按钮都不放
- Roo Code 的任务事件 API 能读状态，没有可靠回写，那就只显示状态
- UI 上没有按钮，比点了没反应的按钮更诚实

## 关于「接通」

- 生成配置、被加载、被信任，是三件事
- 各家还有一层信任确认，用户得手动进去点一次「允许这些 hooks」
- 配置文件存在、进程起来了、开关打开了，全都只到「等待活动」
- 必须收到一条真实任务产生的事件，才允许显示「已接入」
- 别替用户批量信任 hooks。他自己有一堆在跑，你替他勾全部，是在改他的安全边界

## 关于品牌与协议

- Trae 的 CN 版和国际版是两套协议，CN 的验收结果不能挪给国际版
- Cline 的 VS Code 扩展和它的 SDK CLI 是两条路
- Zed 和 JetBrains 的内置 AI 拿不到外部通道，能接的只是显式启动的外部 ACP Agent
- Continue 只能靠轮询快照，会漏短暂状态。能用，但不精确

## 关于会话身份

- Windsurf 用 trajectory_id，Kimi 有任务树，Qoder 区分原生会话和子任务
- Copilot CLI 有并发 ID 要消歧
- Amazon Q 的旧 CLI 包装器拿不到稳定标识，那就只做进程级观察，不碰内容
- 认错会话的后果：代理 A 的问题显示在 B 的卡片上，你点允许，批的是另一件事

## 关于数据

- PV 在这个阶段只会骗自己
- 各页面访问数接近相等，那是遍历
- 页面上找不到的数字，去数据库里找
