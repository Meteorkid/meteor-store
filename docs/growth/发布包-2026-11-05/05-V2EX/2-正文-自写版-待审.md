# 正文

31 个 AI 编程客户端，我做了五个多月，一个都没验完。

31 个目标都有基础通道，都过了契约测试。但契约测试只能说明事件进得来，说明不了岛上那个「允许」按钮按下去到底有没有用。

真正走通的是 Claude Code。2.1.234，隔离环境里读真实文件、以及在岛上拒绝一次写入，这两条我实机跑过。完整审批、并发权限、子代理、TUI 还在验。

往下排：Codex、Cursor、Gemini CLI、Copilot CLI、CodeBuddy 到「契约测试 + 事件类型核对」；Aider、Cody、Amazon Q、Zed、JetBrains 只能包一层显式启动器做观察，交互不覆盖。

为什么这么慢。因为我一开始以为这是个 UI 问题。

同样一件事——代理要写文件了——各家给的接口完全不是一回事。

有的能让你在终端外面回一个允许或拒绝，而且这个结果被客户端当成「用户按了」原生接受。有的只能让你看见它想干什么，你还是得切回去点。这两类要是混在一个界面里，做出来就是个什么都能点、点了都不灵的玩意儿。

我后来把能力拆成三层。观察：知道会话在跑、在等、报错了。应答：代理提问，单选多选或者自由文本，能把答案传回去。审批：决定交回去，而且被当成原生批准。

第三层最难。能做到的没几家。

Gemini CLI 是个典型。它有通知通道，我一开始就把按钮接到通知上了。结果用户点了允许，客户端那边还在等它自己的确认。通知不是批准接口，这件事我栽了一次才明白。

Windsurf 或者 Cascade，前置 hook 能拦住一次调用。但「我阻止了」和「我允许了」是两回事。拿阻断冒充批准，最后是工具直接跑不起来，用户以为软件坏了。

Factory Droid 我只核到观察类事件，没有可用的 PermissionRequest。所以那个客户端上一个审批按钮都没有。

Roo Code 固定在 3.54.0 的任务事件 API，能读任务状态，但没有可靠的回写路径。那就只显示状态。

后来我就不这么干了。接口不支持的，界面上一个按钮都不放。用户能接受「这个功能你这里没有」，接受不了「点了没反应」。

还有件让我意外的事，是配置文件。

生成一份 hooks 配置，跟它被加载、被信任，是三件事。各家基本都有一层信任确认——你写了配置，它还要用户手动进去点一次「允许这些 hooks」。这层不做，文件写得再对，一个事件都进不来。

这条我踩了很久。一开始我以为配置写对了就该通了，调了半天以为是解析格式有问题。后来才发现压根没被信任。

状态就不能只有「已连接 / 未连接」两档。我做成六档：待配置、待授权、待完成设置、等待活动、已接入、检查失败。

关键在「等待活动」和「已接入」之间不能自动跳。配置文件在、进程起来了、开关打开了，全都只算「等待活动」。必须真的收到一条任务产生的事件，才允许显示「已接入」。

反过来也一样。有只读查询接口的就去查，别猜。Codex 能读 hooks 列表，拿得到启用状态、信任状态和定义指纹。查不到就写「检查失败」，不写「未授权」，也不写「已授权」——这两个都是在替客户端下结论。

还有个细节：不写别人的信任记录。用户自己可能有一堆 hooks 在跑，你替他勾上「全部信任」，是在改他的安全边界。

品牌和协议这部分吃过亏。

Trae 的 CN 版和国际版是两套协议。CN 的验收结果不能挪给国际版，我一开始挪了，后来发现国际版根本不认。

Cline 的 VS Code 扩展和它的 SDK CLI 是两条路。扩展通了不代表 CLI 通。

Zed 和 JetBrains 的内置 AI 拿不到外部通道，能接的只是显式启动的外部 ACP Agent，权限还留在编辑器里。

Continue 只能靠 serve /state 轮询快照。会漏掉短暂状态。能用，但我不打算说它精确。

矩阵就是按「客户端 × 形态」一格一格填的。CLI、IDE 插件、桌面端分开记，一格验过不代表隔壁。

会话身份是另一个坑，而且比想象的深。

事件收上来只是开始，还得知道这条事件属于哪个会话。各家给的线索完全不一样：Windsurf 用 trajectory_id，Kimi 有任务树，Qoder 要区分原生会话和子任务，Copilot CLI 有并发 ID 得消歧，Roo Code 可能同时有多个窗口来源。

还有一类没有稳定 ID。Amazon Q 的旧 CLI 包装器拿不到稳定的调用标识，也拿不到回复正文。那就只做进程级观察，不碰内容。

认错会话的后果是：代理 A 的问题显示在代理 B 的卡片上。用户点了个允许，批的是另一件事。这种错比不显示更糟。

矩阵和每个版本的验证记录都在仓库里，docs/compatibility/agent-matrix.json，还有 release-verification 那几个文件。表里写的是「验到哪一步」，不是「支持 / 不支持」。

难看我知道。但我宁可它难看。

客户端本体是闭源的。这条在哪都会被说，提前讲。

安装包是 adhoc 签名，没买苹果的证书。第一次打开会提示「已损坏」，得执行 xattr -cr "/Applications/X Island.app"，或者去系统设置里点「仍要打开」。这步不做，双击就是打不开。

两个问题想问。

你们主力用哪几个客户端？我现在的验收顺序是按「能不能接」排的，不是按「多少人用」排的，这个顺序大概率是错的。

还有，有没有人知道哪家其实有对外审批接口、但我这儿标成了只能观察？那说明我漏了。这种信息比我自己测出来的值钱。
