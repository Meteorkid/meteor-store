# V2EX 发帖步骤（技术帖）

## 前提核对

首帖（产品帖）是 **11-03 晚上**发的，到现在 3 天。这帖是**纯技术内容**，不是产品帖的第二篇——
符合「一个 ID 不连发产品帖」的约定，可以发。

## 操作

1. 打开 https://www.v2ex.com/new/programming
   （或首页「创作新主题」→ 节点选 **程序员**）
2. 标题 → `1-标题-推荐.txt`
3. 正文 → `2-正文-直接粘贴.md`
4. 确认节点是 **程序员**，不是「分享创造」「MacOS」
5. 发布

## 格式：V2EX 的 Markdown 和别处不一样

| 语法 | V2EX |
|---|---|
| `**粗体**` | ✅ 支持 |
| 行内 `` `代码` `` | ✅ 支持 |
| ``` 围栏代码块 | ✅ 支持 |
| `- ` 列表 | ✅ 支持 |
| **表格** | ❌ 不支持（本文没有表格，不用管）|
| **`#` 标题** | ❌ 不渲染（本文用粗体当小标题，正好）|

唯一要留神的：如果发布预览里代码块被压成一行，把三行 ``` 删掉，改成**每行缩进 4 个空格**。

## 关于结尾的产品链接

V2EX 对自家产品链接敏感，但这帖前面有 2,700 字纯技术内容，链接只在最后一行出现一次。

**发完不要再做的事**：
- 不要在评论区补第二遍链接
- 不要自己顶帖（V2EX 会降权，而且老用户看得出来）
- 不要同一天再发任何和产品有关的内容

## 发完怎么接

- 有人问技术细节 → 认真回，别转推销
- 有人指出错误（比如「某家其实有审批接口，你标错了」）→ **这是最好的结果**，立刻记下来改矩阵，并在回帖里说「我改」
- 有人说「这不就是个广告」→ 别辩。回一句「技术部分如果有错请指正，产品那段你可以忽略」，然后停
