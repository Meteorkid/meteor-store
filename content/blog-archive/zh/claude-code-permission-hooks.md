## 一句话版本

Claude Code 的 hook 配置**写了不等于生效**——它还有一层信任确认。你没在客户端里点过「允许这些 hooks」，`PermissionRequest` 事件一次都不会来，而**这种失败没有任何报错**。

这篇把权限链路拆开讲，顺便说明为什么大部分「接了 hook 没反应」的问题都卡在信任这一步。

## 权限请求是怎么走完一圈的

一次工具调用的完整链路：

```
代理决定调用某个工具（改文件 / 执行命令）
        ↓
触发 PermissionRequest hook
        ↓
你的 hook 脚本决定：允许 / 拒绝 / 交给默认流程
        ↓
结果作为「原生批准结果」返回给 Claude Code
        ↓
工具执行，或按拒绝路径处理
```

关键点：**hook 的返回值必须是 Claude Code 认得的批准格式**。你返回一个自定义 JSON，它不会理解成「允许」——它会走默认流程，也就是**弹它自己的确认框**。

所以如果你写了个面板，点了允许，但终端里还是弹了确认框，先检查返回格式，而不是怀疑事件没到。

## 坑一：信任是独立的一层

这是最常见的卡点。链路是三个独立的状态：

| 状态 | 含义 | 怎么确认 |
|---|---|---|
| 配置已写入 | `settings.json` 里有 hooks 段 | 读文件即可 |
| 配置已加载 | 客户端进程启动时读到了它 | 看客户端日志 |
| 配置已被信任 | 用户显式批准过这批 hooks | **必须在客户端里点一次** |

**第三层不做，前两层做得再对也没有事件进来。**

而且失败是静默的：配置文件合法、格式正确、路径没写错，进程也起来了——但 `PermissionRequest` 就是不来。如果你在调试「为什么收不到事件」，先把这三层逐一对一遍。

有一点值得单独提醒：**非交互模式（比如脚本里跑）不会弹授权提示，它会直接自动拒绝。** 所以用命令行跑测试的时候，不要指望能验证 hook 是否被信任——这条路径本身就是不通的。

## 坑二：超时要给够

`PermissionRequest` 的语义是「等用户决定」。用户可能需要几十秒才会看到、才会点。

如果 `timeout` 设成 5 秒（很多示例配置里就是这个值），**用户还没看到，hook 就已经超时了**，然后走默认流程弹它自己的框——你会以为「我的面板没生效」，实际是超时了。

观察类事件（通知、工具调用后）可以给短超时，因为它们不需要人参与；权限请求必须给足够长的时间。这两类混用同一个超时值是常见错误。

## 坑三：hook 里做的事要够快、够安全

hook 是在关键路径上的。它慢，代理就慢；它崩，代理可能也跟着异常。

几条实践：

- **观察类 hook 用 `|| true` 兜底**，别让脚本的非零退出码影响主流程
- **不要在网络请求上无限等待**，加超时
- **不要写别人的信任记录**，也不要批量信任其他 hooks——用户可能有自己的 hooks 在跑，你替他勾「全部信任」是在改他的安全边界

## 怎么确认真的接通了

**别猜，去读状态。** 如果客户端提供了只读的授权查询接口，就查真实状态。

有的话，接入状态至少分六档才诚实：

```
待配置      配置不完整
待授权      客户端明确报告尚未信任
待完成设置  需要导入插件 / 选启动入口 / 连外部服务
等待活动    配置已就绪，但还没收到真实事件
已接入      收到过有效活动
检查失败    读不到授权状态
```

**核心是不要自动推定。** 「配置文件存在」不等于「已接入」；「进程起来了」不等于「已接入」；「开关打开了」也不等于。只有**收到一条真实任务产生的事件**，才允许显示「已接入」。

反过来，读不到状态就写「检查失败」，不要写「未授权」，也不要写「已授权」——这两种写法都是在编。

## 如果你的目的是把确认搬到屏幕外

上面说的都是「怎么正确接 hook」。如果你的目标是**让权限确认不用切回终端**，那还要多一层：hook 的返回值必须是客户端认得的原生批准格式，否则就只是「多收到一个通知」。

**「我收到了一个通知」和「我能替用户批准」是两件事。** 前者只做到了观察，后者才真的省掉了切窗口。

判断方法很简单：**点完允许之后，终端里还会弹它自己的确认框吗？** 会弹，就说明只做到了通知；不弹且工具真的执行了，才是真的批准。

## 小结

1. 信任是独立一层，**没点过就没有事件**，且静默失败
2. 非交互模式不弹授权，会直接拒绝——别用它验证
3. `PermissionRequest` 的超时要给够，它等人的时间可能很长
4. 状态分六档，**不要自动推定「已接入」**
5. 想知道有没有真的「批准」能力，看点完按钮后终端还弹不弹框

第 1 条和第 5 条是最容易踩的，也是最难自己发现的——因为它们的失败方式都是**静默**。
